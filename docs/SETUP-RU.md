> CRM уже создана в Google Таблицах. Используйте таблицу по ссылке из чата, вместо создания новой. Её ID задаётся в закрытых Script Properties.
> Apps Script пока отложен по просьбе владельца. Для тестового деплоя сайта сразу переходите к разделу Vercel; оставьте VITE_SITE_LIVE=false и не задавайте секреты CRM.


# Подключение полного цикла

Это инструкция к подготовленному коду. Ни один пункт ниже не считается выполненным без проверки в аккаунте владельца.

## 1. Данные бизнеса

Уточнить окончательное название, домен, рабочий телефон, публичный email, ответственного за персональные данные, рабочие часы и публичные ссылки Telegram/WhatsApp. Публичный адрес для связи должен быть отдельно подтверждён владельцем.
Точные модели оборудования, цены, гарантии и сроки установки необходимо подтвердить отдельно. Неподтверждённые числа из исходника заменены нейтральными формулировками. Изображения из исходника не являются доказательством выполненных монтажей.

## 2. Google CRM

Создать нативную Google Таблицу импортом `Growatt-CRM.xlsx`. Сохранить в папке ChatGPT. Таблица должна оставаться закрытой.

Открыть **Расширения → Apps Script** в этой таблице. Это должен быть привязанный к таблице проект, иначе меню работы с выделенной строкой недоступно.

1. Вставить содержимое `google-apps-script/Code.gs` в Code.gs.
2. В настройках проекта включить показ appsscript.json и заменить его содержимым файла из проекта.
3. Запустить `setupCrm`, разрешив работу с Google-сервисами в выбранном аккаунте. Запуск повторяем: существующие заявки сохраняются. Проверка заголовков защищает от случайного использования несовместимой таблицы.
4. В **Настройки проекта → Свойства скрипта** задать:
   - `SPREADSHEET_ID` — setupCrm записывает автоматически;
   - `CRM_SHARED_SECRET` — случайная строка минимум 32 символа, лучше 32 случайных байта в hex;
   - `TELEGRAM_BOT_TOKEN` — токен собственного бота;
   - `TELEGRAM_CHAT_ID` — подтверждённый личный чат или закрытая группа;
   - `MAX_DAILY_LEADS` — по умолчанию 100 новых обращений с сайта в сутки UTC.
5. Развернуть **Новое развертывание → Веб-приложение**: выполнять от имени владельца; входящие обращения должны быть доступны без входа посетителя в Google. На аккаунтах с ограничениями администратора это может быть запрещено. Скрипт принимает записи только с проверенной HMAC-подписью сервера; чтения таблицы через веб-приложение нет.
6. Скопировать URL развертывания, заканчивающийся `/exec`. При изменении скрипта обновлять версию существующего развертывания.
7. После настройки Telegram запустить `installTriggers`. Он установит проверки Gmail и доставку Telegram каждые пять минут и журналирование ручных правок.

**Gmail:** скрипт обрабатывает письма с ярлыком `CRM/Заявки`, начиная с момента setupCrm. Для старых обращений можно осознанно изменить `GMAIL_SINCE_MS`. Письма должны получать ярлык вручную или фильтром Gmail. Входящие ответы в той же цепочке связываются с существующей заявкой; письмо в новой цепочке создаёт отдельное обращение. По совпадению имени/телефона сделки автоматически не объединяются.
Вкладка История хранит ID обработанных писем. Не удаляйте её для «очистки» — иначе возможен повторный импорт. Начальный текст письма хранится до 2000 символов, полная переписка остаётся в Gmail; вложения автоматически не копируются.

**Telegram:** новая заявка записывается в очередь в момент сохранения. Отправка выполняется по расписанию, обычно с задержкой до следующего запуска; это не гарантированная доставка за пять минут. До шести попыток с увеличением интервала. Затем статус «Ошибка» и ручной повтор через меню CRM. Telegram не поддерживает ключ идемпотентности sendMessage: если он принял сообщение, а ответ потерялся, повтор может отправить уведомление ещё раз. Дубля заявки в CRM при этом не создаётся.

**Docs:** перезагрузить таблицу, выделить строку заявки, меню Growatt CRM → Создать предложение. Создаётся закрытый черновик, который нужно заполнить и проверить. Автоматической отправки клиенту нет.

## 3. GitHub

Используется отдельный репозиторий https://github.com/odessamama2026/growatt-energy. Владелец создал его публичным. Не коммитьте секреты, выгрузки заявок или персональные данные клиентов.
Загрузить исходники из архива без node_modules, .vercel, логов, секретов и локальных файлов авторизации. Включён .gitignore и GitHub Actions. После загрузки дождаться успешных Build and CRM checks.

## 4. Vercel

Импортировать новый GitHub-репозиторий. Оставить автоматическое определение TanStack Start/Nitro; Node 24. Команды уже в vercel.json.

Сначала создать Preview. Для проверки форм задать серверные переменные:
- `GOOGLE_CRM_WEBAPP_URL` — URL Apps Script `/exec`;
- `CRM_SHARED_SECRET` — тот же секрет, что в свойствах Apps Script;
- `SITE_URL` — окончательный HTTPS origin сайта без завершающего `/`;
- `LEAD_ALLOWED_ORIGINS` — точные разрешённые origins через запятую. Для тестирования добавить конкретный preview-origin; никаких `*`.

Не используйте клиентский префикс VITE_ для этих секретов. Прямой доступ к Google Таблицам с браузера не нужен.

Публичные значения — из `.env.example`. Для реального запуска установить `VITE_SITE_URL`, телефон, email и ответственного, затем `VITE_SITE_LIVE=true` **только для Production**. В Vercel Preview сборка принудительно остаётся noindex. Изменение VITE-переменных требует новой сборки.

Перед запуском проверить весь путь: форма → новая строка в таблице → Telegram → изменение статуса → запись в Истории. Дважды отправить один и тот же запрос: строка должна остаться одна. Отдельно отправить тестовое письмо с ярлыком и ответ в той же цепочке. Тестовые письма отправлять только на согласованный адрес.

## 5. GA4

В Google Analytics создать **отдельный ресурс для Growatt**, а не использовать G-7EW22VKCVG от сауны. Задать часовой пояс Europe/Kyiv и валюту UAH после подтверждения владельцем, создать веб-поток для окончательного домена.
Полученный G-ID установить в `VITE_GA4_ID` для Production, выполнить новый деплой.

Подготовленные события: `generate_lead` (только после подтверждения сохранения), `form_open`, `click_phone`, `click_telegram`, `click_whatsapp`, `click_email`. Контактные данные и тексты заявки в события не входят. Аналитика запускается после согласия пользователя.
Для точной проверки убедиться в GA4 Realtime/DebugView, что `generate_lead` появляется один раз после успешной отправки. Отметить его как ключевое событие. Если включено расширенное измерение форм, не считать `form_submit` второй конверсией той же заявки. Не включать сбор пользовательских данных без отдельного решения.

## 6. Search Console

После выбора и подключения домена создать Domain property, добавить выданную Google TXT-запись у DNS-провайдера и проверить владение. Альтернатива — URL-prefix и HTML meta verification: токен можно задать в `VITE_GOOGLE_SITE_VERIFICATION` с новым деплоем.
После публичного запуска убедиться, что /robots.txt разрешает обход, /sitemap.xml содержит реальные canonical URL, страницы не имеют noindex. Подать sitemap.xml и проверить главную через URL Inspection. Регистрация не гарантирует индексацию или позиции.

## Ограничения первой версии

Нет внешней БД. Квоты Apps Script остаются; ограничения по IP используют кеш и являются best effort, а суточный лимит хранится в свойствах. Для значительного спам-потока усилить ограничения на Vercel перед обработчиком.
Все сотрудники с правами редактирования таблицы потенциально могут менять критичные поля. Не выдавать доступ посторонним; сначала пользоваться одному владельцу. Конкурентные массовые ручные сортировки во время обработки не рассчитаны на большую команду.
Нет проверки доставляемости телефона, автоматической классификации произвольных писем AI, копирования вложений, автоматического ответа клиентам, финансового учёта или гарантированной доставки уведомлений exactly-once.
